# Simplify spec — show rules replace the tree-walking state machine; drop `variant`

## 0. Provenance

This document amends `specs/20260901-mvp3.md` in two independent places:
§2.1 (rendering mechanism) and the parts of §2.2/§3 describing
`entries.typ`'s internal shape (§1-6 below), and separately §2.6's
paragraph on `variant` plus §10's terminology-table line pairing
`variant` with `accent`/`accent-scope` (§7 below). Everything else in
that document stands: the markup contract (mvp3 §5), the design tokens
(mvp3 §4), the example content (mvp3 §8), and the Markdown/Pandoc
workflow (mvp3 §6). `cv()`/`letter()`'s public parameter *list* does
change — §7 removes `variant` and reorders the opt-in feature flags — but
the parameters' meaning and the markup contract are otherwise unaffected.

`specs/20260821-design-cyber.md`, `20260828-mvp1.md`, and
`20260830-mvp2.md` were already fully superseded by `20260901-mvp3.md`
(its own §0) and aren't independently amended here.

§2.6's freeform-section-name decision (no closed vocabulary, no
compile-time `assert`, backed by `check_ats.py`'s regression check)
carries forward unchanged — untouched by either amendment below.

## 1. Why the state machine went

§2.1 chose full content-tree introspection — split the body at H1/H2
boundaries, classify each section's shape, re-emit fresh `heading()` calls —
for two stated reasons. Both dissolved on inspection:

- **Every field the walk extracted positionally is discoverable from a node's
  own content.** Entry title/date come from the H2's own text. Org/location
  and the logo come from the meta paragraph's own children. The code line is
  a paragraph that is nothing but a `raw` span. The note is a `list.item`'s
  own trailing `quote`.
- **Re-emitting `heading()` solved a problem that does not exist.** A `show
  heading` rule whose replacement contains no `heading()` call still produces
  a correct, correctly-nested PDF outline (finding 1).

The decisive argument, though, is one the original spec did not make: **the
walker silently lost content.** `render-entry-body` scanned positionally —
prose until the first `list.item`/`raw`, then bullets, then a code line — so
an inline `` `code` `` span *inside a prose sentence* satisfied the `raw`
terminator and discarded the remainder of the entry. A CV with
`` using `PyTorch` in production `` mid-paragraph lost the rest of that
sentence, both following bullets and the real code line, with no warning.
Show rules cannot fail that way: every element is styled where it sits, so
markup the contract did not anticipate renders imperfectly rather than
vanishing.

This is an internals-only change. `cv()`/`letter()`'s parameters and the
markup contract are unchanged. Rendered output is *nearly* unchanged — §5
lists the three deliberate differences.

## 2. Architecture

`entries.typ` exports rule factories; `cv()` registers them at the point it
knows the call-specific values (`accent-list`, fonts, `show-logos`, …):

| rule | element | does |
|---|---|---|
| `section-header-rule` | `heading.where(level: 1)` | chevron, accent-coloured name, rule line; owns the gaps above and below the whole header block |
| `entry-heading-rule` | `heading.where(level: 2)` | title flush-left / date flush-right, split on `"\|"` |
| `meta-line-rule` | `emph` | org/location line, logo extraction and placement |
| `note-rule` | `quote.where(block: true)` | the muted note under a bullet, or nothing when `show-notes: false` |
| `list-rule` | `list` | wraps the list in a block so it has a `below` to collapse against |
| `skills-item-rule` | `terms.item` | one padded monospace label + description per row |
| `paragraph-rule` | `par` | code line (indented, chrome) or ordinary prose |

Plus one show-set in `cv()`: `show raw: set text(font: font-chrome, size:
size-code, fill: muted)`.

### 2.1 Declared cross-node state

Three channels, all the same pattern — a later sibling reads what an earlier
sibling set. They are the design's actual coupling and are named here rather
than presented as exceptions to a node-locality claim:

- `counter("cv-section")` — accent rotation. Stepped by every H1, read by the
  H2, emph and terms.item rules. (Typst's built-in `counter(heading)` does
  not advance under `numbering: none`, finding 2, so a named counter is the
  correct mechanism regardless.)
- `counter("cv-entry")` — reset by every H1, stepped by every H2. Lets a
  section's first entry take `space-rule-to-content` instead of
  `space-entry`; without it every entry-shaped section's first entry sits
  4.8pt lower than a freeform section's first line.
- `state("cv-meta-expected")` — set by every H2, consumed by the next `emph`,
  cleared by every H1. This is what keeps meta-line styling off ordinary
  inline italics. It is irreducible: the markup contract defines the meta
  line *by its position* (the emph-only line under an entry title), and
  position is exactly what a matched element does not know.

### 2.2 The code line is classified by its own ambient style

`cv()`'s `show raw` show-set replaces Typst's built-in `raw` defaults (DejaVu
Sans Mono at 0.8em). Typst propagates a declared style up to the enclosing
paragraph *only* when the paragraph consists of nothing else, which makes
"is this paragraph one raw span" answerable from the paragraph itself —
no marker content, no state. Measured from inside `show par` (finding 3):

| paragraph | ambient |
|---|---|
| entirely one `raw` span | `ibm plex mono` @ `9pt` |
| `raw` span leading, trailing, mid-prose, or two of them | `ibm plex sans` @ `10.5pt` |

The test checks font **and** size, because the chrome font alone is not
unique to code — `section-header-rule` sets it too, at 14pt, and that set
lands in the heading's own paragraph ambient just the same. `size-code` is a
token in `theme.typ` precisely because the show-set and the test must agree
on it. For the same reason there is no show-set for the headings: it would
put the chrome font into a section heading's ambient and `paragraph-rule`
would read the heading as a code line (observed, as a 10.56pt indent on
every section title).

### 2.3 Why the meta line is not classified the same way

`emph` cannot use the ambient trick, for a reason that overturns §2.1 of the
first draft of this document: **emph's italic toggle is applied around
whatever a `show par` rule returns and cannot be overridden from inside it.**
Verified — with a `show par` rule rendering a whole-line emph, neither `set
text(style: "normal")` nor `text(style: "normal")[…]` has any effect; the
output is italic either way. A `show emph` replacement is not subject to the
toggle. So the meta line is rendered from `show emph` and gated by
`cv-meta-expected` (§2.1).

The earlier claim that `show par` cannot see the meta line because Typst
fragments a paragraph containing an inline image is **wrong, and was the
wrong reason to reach the right conclusion**. The fragmentation is real —
children are `tag|box(image)|space|text|space|text|tag` — but nothing is
lost: the `box(image)` node is present and findable, and `extract-meta`
walks a flat child list either way.

### 2.4 Skills rows

A per-item `show terms.item` rule cannot see its siblings, so it cannot
compute a shared max-label width; a container-level `show terms` rule sees
`it.children` only after every child's own rule has already run (finding 4),
so it cannot hand one down either. Rather than reintroduce a tree walk to
work around that, the label column is simply a constant:
`skills-label-chars` in `theme.typ`. Padding is `calc.max(width - len, 1)`
so an over-long label still separates from its description instead of
failing on a negative repeat count.

### 2.5 Bullets and notes

Bullets need no rule: `list.item`'s default rendering already places a
trailing `quote` correctly. Only `show quote.where(block: true)` is needed,
restyling the note in place. Reconstructing `list.item` recurses (finding 5),
so leaving it alone is both simpler and the only safe option. List
indent/marker/spacing is one ambient `set list(...)` in `cv()`.

### 2.6 Positions are computed or tokenised, never hand-tuned

No `place()` in the package carries a measured magic constant any more:

- Both chevrons (`entries.typ`, `letter.typ`) use `place(left + horizon, dx:
  -mark-gutter, …)`. `horizon` centres the mark against a block holding one
  line, so no vertical offset is needed at all. This replaced two *different*
  hand-tuned values (`-0.175pt`, `-1.175pt`) doing the same visual job.
- The logo offset is `-(space-header-line + title-height)`, with
  `title-height` measured from an explicit text style rather than the
  ambient. The previous hand-tuned `-14.8pt` turns out to be exactly that
  quantity (measured: −14.78pt) — it was the top of the title+meta group all
  along, reached by trial and error.
- `mark-gutter`, `logo-width`, `logo-height`, `logo-gutter` and
  `space-code-indent` are `N * u` tokens, checked by `check_spacing.py`.
  `space-code-indent` in particular replaced a `measure([•])` call — see §4.

Type sizes remain literals at their one owning call site, per
`20260901-mvp3.md` §4; `size-code` is the single exception, and only because
two places must agree on it (§2.2).

## 3. Verified Typst mechanisms

Compiled with the repo's bundled `.venv/bin/typst` and inspected with
`pypdf`/`pymupdf`, not assumed from documentation.

1. **No heading re-emission needed.** A `show heading` rule whose replacement
   contains no `heading()` still yields a correct outline — confirmed on the
   real `examples/typst/cv.pdf`: all six H1s with their H2s, correctly
   nested, in document order.
2. **`counter(heading)` does not advance under `numbering: none`**, while a
   named counter stepped inside the rule does.
3. **A declared style propagates to the enclosing paragraph only when the
   paragraph is nothing but that element** — the table in §2.2.
4. **Children realize before their container.** A `show terms` rule sees
   `it.children` only after each `show terms.item` has run, so state written
   by the container never reaches the items.
5. **Returning a fresh instance of the matched element from its own show rule
   recurses** ("maximum show rule depth exceeded"), for `list.item` and
   `terms.item`. Returning the original `it` is safe; returning different
   content is safe.
6. **A PDF/UA-1 structural tag survives from the matched element's
   identity.** `show terms.item` returning plain content compiles clean under
   `--pdf-standard ua-1`; a `show terms` rule that discards the per-item
   elements does not ("list (L) may not contain marked content directly").
7. **A bare `list` has no block-level `above`/`below`** to collapse against a
   following block declaring `above: 0pt` — the next block overlaps the
   list's last line. Hence `list-rule`.
8. **Block spacing is `max(prev.below, next.above)`, not a sum** — measured
   with `here().position()`. This is what lets each rule declare only its own
   gaps.
9. **`block(sticky: true)` keeps a block with the content that follows** —
   supported in the bundled 0.15.1, used for both heading levels (§5).

## 4. The bug class this design is prone to

A rule's `context` reads the **matched element's** ambient style chain, not
the document's. Three instances were found, all the same shape:

1. `3em` read from a heading-level-2 rule resolved against a 12.6pt ambient
   and from an emph rule against 10.5pt — the same nominal constant, two
   different sizes.
2. `measure([•])` inside `paragraph-rule` resolved against the *raw*
   ambient (`dejavu sans mono` @ `8.4pt`, Typst's own default), returning
   5.06pt instead of 4.16pt and shifting every code line 0.9pt right.
3. A heading show-set putting the chrome font in a heading's ambient, making
   `paragraph-rule` read the heading as a code line.

The rule that follows from all three: **inside a show rule, never read an
`em`, a `measure()`, or an ambient property you did not put there yourself.**
Measure from an explicit `text(...)`, or use a token. Instance 2 is why
`space-code-indent` exists; instance 1 is why the logo geometry is fixed;
instance 3 is why there are no heading show-sets.

The remaining `em` values in the package (`cursor-gap`, `draw-cursor`'s
sizing, both `par` `leading`s) are deliberately relative to their own call
site's text size and are not read from two places, so none is exposed.

## 5. Differences from the pre-rewrite rendering

Checked span by span against the pre-rewrite PDFs. Three differences, all
deliberate, now locked into `tests/layout_baseline.json`:

1. **Skills description column +10.8pt.** `skills-label-chars` is a fixed 12;
   the old per-section max happened to be 10 for the example content.
2. **Logo variant: entries sit ~3.09pt tighter each.** The logo is `place`d
   out of flow, so an entry no longer reserves vertical space for a
   decorative mark; the old grid cell forced each entry header to the logo's
   height. Logo box +0.6/+0.4pt and `mark-gutter` +0.09pt from the `N * u`
   tokens.
3. **+0.13pt per entry** between a meta line and the body under it —
   invisible (0.38pt over a full page), accepted rather than chased.

**Page-break behaviour changed and is not fully equivalent.** The walker
wrapped title+meta+body in one `breakable: false` block, so an entry never
split. `sticky: true` on both heading levels keeps a title with its meta
line, but the bullets can still break to the next page, leaving a two-line
widow (reproduced deliberately). The old behaviour had its own cost — a long
entry was pushed wholesale to the next page, leaving a large gap — so this is
a trade, not a pure regression. Closing it would need a fourth state channel,
which is not worth it.

## 6. Verification

`make test` runs contrast, spacing, ATS-extraction and — new — rendered
layout. `tests/check_layout.py` compares every text span's page and
position in all 8 example PDFs against a committed baseline, at 0.01pt.
Findings in §4 were all caught by hand-comparing output after the fact, and
one still slipped through to a shipped PDF; this makes that comparison
mechanical. Regenerate with `--update` only after looking at the PDFs.

Out-of-contract markup is checked by hand against a scratch CV containing an
inline `` `code` `` span mid-prose (must not truncate the entry — the
walker's bug) and inline `_italics_` mid-sentence (must stay ordinary
italics, not become a meta line).

## 7. Dropping `variant` — grayscale becomes an accent choice, not an axis

### 7.1 Why `variant` goes away

`variant: "themed" | "plain"` had exactly two effects, both in `cv()` and
`letter()`: collapse `accent-list` to `(fg,)`, and suppress the
header/footer cursor mark (`show-marks`). Nothing else in the codebase
branched on it. Those are two independent, already-general mechanisms —
picking an accent color, and (previously) toggling a decorative mark — not
a property that deserved its own named axis. `cv-plain.pdf` (the only
build that ever used `variant: "plain"` — there is no `letter-plain`
target) needed a grayscale-safe accent color and its opt-in features left
off; both are already expressible with the parameters `cv()` already has.

### 7.2 What replaces it

- **`accent-presets` gains a `gray` entry** (`src/theme.typ`), a literal
  `rgb("#3c3836")` — the same hex as `fg` — alongside `red`/`green`/
  `friggeri`. Passing `accent: "gray"` (or `--input accent=gray` from the
  Makefile) gets the old `plain` accent-collapse behavior through the
  normal accent-resolution path, with no special-cased string comparison
  anywhere in `cv()`/`letter()`.
- **`show-marks` is gone entirely.** `header-block`/`footer-block` now
  always draw the cursor mark; there is no longer any parameter or
  internal flag that suppresses it. This is a real (if minor) visual
  change: `cv-plain.pdf`'s header/footer cursor, previously hidden, now
  renders in the `gray` accent color like every other build's cursor
  renders in its own accent color.
- **No new parameter was added to replace `variant`.** `cv-plain.pdf` is
  built by passing `accent: "gray"` plus the existing feature flags
  (`show-icons`, `show-footer`, `show-logos`, `show-notes`) explicitly
  off — the same vocabulary every other build already uses, just with
  different values.

### 7.3 Parameter order

While every call site touching these parameters was already being edited,
the four opt-in feature flags were reordered to read the same everywhere:
`show-icons, show-footer, show-logos, show-notes` (`letter()` only has the
first two). This applies to `cv()`/`letter()`'s own signatures, both
Pandoc templates, both hand-written `.typ` examples, and both Markdown
front-matter files. Purely cosmetic — Typst calls into these functions are
all keyword-argument calls, so the declaration order was never load-bearing.

### 7.4 `show-icons`/`show-footer` default to `true` for `cv`, not for `letter`

`examples/typst/cv.typ`'s own `sys.inputs.at("show-icons"/"show-footer",
default: ...)` fallback changed from `"false"` to `"true"`, and
`examples/markdown/cv.md`'s front matter now sets both to `true` directly
— so `examples/typst/cv.pdf`/`examples/markdown/cv.pdf` (the "cyber"
default look) no longer need any `--input`/`--pdf-engine-opt` flags at
all from the `Makefile`. `cv-friggeri`'s flag list dropped the now-
redundant `show-icons=true show-footer=true` for the same reason.
`cv-plain` now has to pass `show-icons=false show-footer=false` explicitly,
since the example's own default flipped.

`letter()` keeps its old defaults (`false`) and its `Makefile` wiring
(`LETTER_INPUTS`/`LETTER_FLAGS`, unchanged besides the reorder) —
`cv()`'s own function-level defaults were never touched either; only the
*example*/*template* call sites' `sys.inputs` fallback values changed, and
only for `cv`. This is deliberate, not an oversight: `cv` has three build
variants sharing one source file/template (`cv`, `cv-plain`,
`cv-friggeri`), so its `sys.inputs` layer is doing real work and is worth
simplifying at the default level; `letter` has exactly one build today, so
its `sys.inputs` plumbing was left as-is, kept as room for a future
per-build override (e.g. an `accent=` variant) without re-plumbing later.

### 7.5 Layout consequences

The markup contract, design tokens, and the Markdown/Pandoc workflow
mechanism are all unaffected. `check_contrast.py` and `check_spacing.py`
need no changes — the new `accent-presets.gray` token is picked up
automatically by `check_contrast.py`'s existing regex-based
`parse_accent_presets` (it requires a literal hex, which is why `gray` is
`rgb("#3c3836")` rather than a `fg` alias), and passes at 11.60:1 —
identical to `fg`, since it's the same value.

`check_layout.py`'s baseline *did* need regenerating, once: with
`show-marks` gone, `cv-plain`'s header now draws the cursor mark it
previously suppressed, and that mark's box height nudges the tagline line
2.8pt further down (`examples/{typst,markdown}/cv-plain.pdf`, confirmed
visually before running `--update`) — the only span movement anywhere in
the 8-PDF matrix. Every other build's `show-icons`/`show-footer`/accent
values resolve identically to what they were before (§7.4), so nothing
else moved.

## 8. Letter: explicit salutation/closing, dedicated paragraph spacing

`letter()` no longer hardcodes "Dear Hiring Manager," or "Best regards," +
`author.name` — both were baked into the template regardless of the
example content, so every letter read the same regardless of what was
actually written in `examples/markdown/letter.md`/`examples/typst/letter.typ`.
The salutation and sign-off are now ordinary paragraphs in `body`, authored
like the rest of the letter.

The date block's `above:` gap now reuses `space-header-to-section` (was
`space-paragraph`), matching the CV's identity-rule-to-heading gap — the
date sits beside a chevron the same way a section heading does, and its
text now takes the same font/weight/size/color as a CV entry's date
(`entries.typ`'s `entry-heading-rule`) rather than the ambient `fg`.
Paragraph spacing (`set par(spacing:)`) is now a `paragraph-spacing:`
keyword parameter, defaulting to a new `space-letter-paragraph` token
(`2 * u`, `theme.typ`) instead of reusing the CV's `space-paragraph` — the
letter's own rhythm no longer has to track the CV's.

`check_layout.py`'s baseline was regenerated to match (both letter PDFs'
span positions moved; nothing else did).
